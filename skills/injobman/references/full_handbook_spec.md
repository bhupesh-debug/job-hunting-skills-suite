# Full Handbook Spec (only build when user selects "Full handbook")

## JD deep-dive
For every responsibility/qualification: meaning, why employers ask, day-to-day use,
how recruiters evaluate it, common candidate mistakes, and how the candidate's real
background maps to it (or an honest gap flag).

## Interview bank — all categories
HR, Behavioral, Technical, Role-Specific, Domain Knowledge, Situational, Case Study,
Leadership, Analytical, Communication, Managerial, Executive, Industry-Specific.
Use the question-card format in `interview_prep_framework.md` for every question, but
cap total questions at the true 80/20 set per category (~5-10 each, not exhaustive) —
quality and relevance over volume. End each category with an "80/20 Summary" of the
2-3 highest-ROI questions in that category.

## Signature preparations (always include in full mode)
Tell Me About Yourself, Resume Walkthrough, Why This Company, Why This Role, Why Hire
You, Strengths/Weaknesses, Biggest Failure, Biggest Achievement, Salary/Offer
Negotiation, Questions to Ask, Closing Pitch.

## STAR story library
6-10 stories pulled only from the candidate's real experience, tagged by competency
(leadership, ownership, conflict resolution, problem solving, etc.), reusable across
multiple questions.

## Workplace playbook
Daily/weekly/monthly planner template, time management, meeting/email management,
reporting cadence, KPIs relevant to the role, common early-tenure mistakes, best
practices — kept generic/role-appropriate, not fabricated as if already experienced.

## Do's / Don'ts / Avoid
Cover resume, cover letter, interview, workplace communication, virtual interview
etiquette, salary talk, recruiter interactions, onboarding.

## Email templates
Thank-you, recruiter follow-up, salary negotiation, offer acceptance, offer decline,
networking follow-up, LinkedIn connection request. Keep these as adaptable templates
with bracketed placeholders, not pre-filled with invented specifics.

## Formatting
Table of contents, section dividers, comparison tables where useful. Build as a
multi-section .docx (or split into a few files if very long) via the docx skill —
do not attempt hidden/cloaked text anywhere in the document (see SKILL.md hard rules).
